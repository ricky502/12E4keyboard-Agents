# Agentpad：飞书 Agent 统一状态协议

适用对象：探春、黛玉、湘云、香菱、宝钗、莺儿。所有状态消息均发送到既有的 Agentpad 飞书状态群；不发送密钥、用户内容或任务正文。

香菱虽然使用企业微信智能机器人作为对话入口，状态仍必须镜像到该飞书状态群。键盘客户端只订阅这一条状态总线，因此不能也不应使用香菱的企业微信 Bot ID/Secret 另建连接（同一企业微信机器人只能由其 Agent 服务保持一条有效长连接）。

## 灯态含义

| Agent 实际状态 | 发送值 | 键盘效果 |
| --- | --- | --- |
| 已就绪 / 未在执行 | `idle` | 白色呼吸 |
| 正在执行任何步骤、工具调用或等待工具结果 | `thinking` | 蓝色常亮 |
| 整个任务已结束，结果已发出 | `complete` | 绿色常亮，用户按该 Agent 键后变白 |
| 只能等待用户作出批准、选择或补充信息 | `needs_input` | 琥珀色呼吸 |
| 任务无法继续或出现明确异常 | `error` | 红色闪烁 |

## 按发起人区分占用（本机客户端，无需刷机）

每条任务的首次 `thinking` 可带 `owner`（飞书发起人 open_id）和 `chat`（原会话 ID）。后续保活或结束若只有相同 `task_id`，本机继承该任务首次记录的归属。不同 `task_id` 独立计数，一个人的任务完成不会覆盖另一个仍在工作的任务。

飞书 `open_id` 是按应用生成的，同一用户在不同 Agent 机器人下可能不同。在本机 `config.json` 用 `feishu_status_self_owners` 为每个 Agent 分别设置自己的 open_id，例如 `{"xiangling":"ou_...","tanchun":"ou_..."}`。不可把单个 open_id 套用于所有 Agent。工作状态的灯色为：

| 活跃任务的归属 | 灯色 |
| --- | --- |
| 只有自己 | 蓝色常亮 |
| 自己和他人同时在用 | 黄色常亮 |
| 只有他人在用 | 红色常亮（区别于故障红色闪烁） |
| 没有归属标记、或该 Agent 尚未配置自己的 open_id | 单个活跃会话沿用蓝色；无法可靠区分是谁。两个不同 owner 同时活跃时仍显示黄色 |

只有该 Agent 已配置“自己的 open_id”时，红灯才表示非自己；若除马立荣外还有第三人，红灯不能单独证明是马立荣。无任务在执行时，仍沿用原来的完成绿灯、空闲白色呼吸等含义。首次接入或重启后须等新的飞书事件，历史消息不会回放。若要跨所有机器人统一识别用户，也可让远端改发同租户跨应用稳定的 `user_id`，届时本机才可使用单一用户 ID。

## 必须遵守的发送规则

1. 收到并开始处理一个任务时，立刻发送一次 `thinking`。
2. 使用同一个 `task_id` 贯穿该任务的全部状态消息。
3. 任务仍在执行时，每 60 秒发送一次 `thinking` 保活；调用工具、等待子任务、生成长文、联网或等待接口均属于执行中。
4. 只有整个任务不再有后续步骤、且最终结果已经发送时，才发送 `complete`。阶段性产物、子步骤结束、已开始下一轮工作，均不能发送 `complete`。
5. 只有真正需要用户处理才能继续时才发送 `needs_input`；不要把普通的工具等待、排队或后台处理当作等待输入。
6. 一项已完成任务被用户在键盘上确认后，如 Agent 收到新任务，仍必须重新发送 `thinking`；不能假定旧灯态仍有效。

## 消息格式

每次均只发送一行，允许前面带飞书的 @ 提及：

```text
[AGENTPAD] {"agent":"tanchun","state":"thinking","task_id":"agent-20260831-001","owner":"ou_...","chat":"oc_..."}
```

其中 `agent` 必须是对应 Agent 的固定英文标识：

```text
tanchun / daiyu / xiangyun / xiangling / baochai / yinger
```

## 上线验收

对每个 Agent 各执行一次真实任务，验证顺序必须为：

```text
thinking → （至少一次 60 秒保活 thinking） → complete
```

期间键盘应持续为蓝色；只有最后 `complete` 才转绿色。按下对应的绿色键后应恢复白色呼吸。不得用其他 Agent 代发、不得用人工代理消息替代真实生命周期钩子。
